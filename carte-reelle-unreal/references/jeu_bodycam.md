## 1. Kit de modding et versions

- **Aucune voie officielle** : pas de Workshop ni de kit du studio (réponse de l'équipe, 08/11/2025). La seule chaîne est un kit communautaire (Map Kit) + un installeur (Map Importer), outils tiers publics sous licence MIT ; aucun fichier du jeu dans le kit. « Creator Tool » : impasse (téléchargement verrouillé, format non publié).
- **Version du kit** : Map Importer v0.2.1 (06/11/2026, dernier commit de l'installeur le 06/11, du kit le 08/10, aucun fork) ; clone local au commit `b61c5d0` (13/11). La veille `veille_kit/verifier_kit.ps1` interroge l'API GitHub publique (`-Boucle 30` ; code 0 = rien, 1 = nouveau + `NOUVEAU.flag`) : relevé du 17/11 8 h 35 « inchangé ».
- **Moteur : Unreal 5.5 exigé** (5.5.4 ; « 5.6 et plus ne marchent pas »). Une carte enregistrée en 5.8 ne s'ouvre pas en 5.5 : on reconstruit en 5.5 par les scripts, on ne copie pas. Le PC n'avait que 5.8 au départ ; la construction sans interface était identique en 5.5 et 5.8 (63 s). Fixer la version du moteur dès le jour 1.
- **Jeu** : v0.9 « The Dead & Damned » le 13/11/2026, build Steam 26647288 (l'ancien kit visait 25505592) ; v0.9.1 le 16/11 (correctifs, sans mention des mods). **Easy Anti-Cheat actif depuis la v0.9** (parties multijoueur P2P PC).
- **Prérequis du kit** : projet `BodycamSandbox.uproject`, Git Bash, Python 3 + Pillow (installé avec l'accord du joueur). Commande : `Scripts/newmap.sh <Id> "<Nom affiché>" <capture.png> <version>` ; sortie `Saved/maps/<Id>/out/<Id>.bcmap` (zip : `card.json`, `thumb.png` 1024×512, `paks/`, `menu/`).
- **Règles du kit** (refus sinon) : Id `^[A-Za-z][A-Za-z0-9]{1,12}$`, ne finit pas par Prison, ne contient pas GameMode/Paintball/lobby ni un nom de carte du jeu (« Pit » en sous-chaîne interdit) ; version strictement supérieure à l'installée ; nom et description = texte « Base » unique (pas de `.locres`) → écrire les deux langues dans le nom (« Carrière / Quarry »).
- **Ce que fait `newmap.sh`** [vu] : contrôle Id/photo/niveau → `kit_game_files.py` (lit les `pakchunk*` du jeu avec UnrealPak) → sonde du niveau → correctif Hardpoint → 7 niveaux de mode `GM_Maps/<Mode>/<P>_<Id>` (HP, TDM, DM, VS, GG, BB, WM) avec navigation cuite (rayon d'agent 15) → `make_menu.py` → cuisson + contrôle Hardpoint R1-R12 → `make_paks.py` (refuse toute importation `/Game` ou `/Engine` non empaquetée ni présente dans les paks du jeu) → package → install.
- **Exigences sur le niveau** : ≥ 4 `PlayerStart` à plat (tagués 1/2 ; nous : 6 + 6), exactement 1 `DirectionalLight` et 1 `SkyLight`, **exactement 1** `HardPointZone_C` et 2 à 32 `BP_PointZonePreview_C`, tous les assets sous `Content/Sandbox/<Nom>/`, aucun `RecastNavMesh` ni `NavMeshBoundsVolume`, pas de `/Engine/BasicShapes` (générer `SM_LC_Cube/Cylindre/Sphere`), Nanite coupé, **une texture par défaut pour chaque paramètre de texture** (sinon carte grise).
- **Limites du kit** : carte de « quelques centaines de mètres » (navigation des bots) ; parties **privées avec bots seulement** ; Landscape, foliage, World Partition non documentés [non vérifié].
- Variables d'environnement : `BCM_UE`, `BCM_UNREALPAK`, `BCM_STEAM_ACF`, `BCM_GAME`, `BCM_NAV_OVERRIDE`, `BCM_WEATHER`, `BCM_AUTHOR`, `BCM_DESCRIPTION`, `BCM_STAGES` (`"cook paks package"` fabrique un paquet **sans installer**).

## 2. Chaîne de construction dans l'éditeur

- **Un script d'éditeur construit tout** (`unreal/construire_niveau.py`, + `architecture.py`, `generer_maillages.py`, matériaux, végétation, lointain) lancé par `construire.bat` → `UnrealEditor-Cmd -run=pythonscript`. Modes : construire, `verifier`, `capturer`, `cuire` (textures de feuillage), `copier`, `inventaire`, `assets`, `supprimer`, `importer`. Construction : 61-121 s ; cuisson 3 min 12 ; cuisson GPU de textures ~2 min ; navigation ~9 s par mode ; paquet `.bcmap` 225-360 Mo. Le rapport `Saved/<Carte>/rapport.json` fait foi, pas le code de sortie (la navigation journalise `LogCrowdFollowing: Error` et sort en code 1, rattrapé si `TERMINÉ` est écrit).
- **Pas de Landscape** : le kit n'en a aucun exemple et `ALandscapeProxy::Import` n'est pas exposé à Python. Terrain = dalles de maillage avec collision : 16 dalles de 420×462 m (zone + 120 m), décor de 1 008 m (maille 8 m), horizon de 4 096 m (maille 32 m). Import `.r16` en Landscape (505×505, Scale XY 200, Z 100) prévu, **jamais exécuté** [non vérifié].
- **Commandlet (sans interface)** : `StaticMeshEditorSubsystem` = None, `spawn_actor_from_object` = None, `new_level` refuse un chemin existant, tirs de rayon inopérants après rechargement d'un niveau, `unreal.Transform(rotation=…)` veut un Rotator, `render_target_create_static_texture2d_editor_only` plante (cuisson via PNG). Les captures exigent `-ExecCmds="py <chemin sans espace>"` (`-ExecutePythonScript` ferme l'éditeur à la fin) ; le dossier `Saved/<Carte>/captures` est vidé à chaque passe.
- **Collision** : tout maillage importé passe en `CTF_USE_COMPLEX_AS_SIMPLE` + profil `NoCollision` pour le décor lointain. Contrôle par rayons dès la première construction (grille de 8 m, 1 m dans la zone, seuil d'impact 40 cm, simple ET complexe), objets flottants (seuil 8 cm, correction « écart + 2 cm », base au point bas de l'emprise), véhicules (boîte + 30 cm, `caler_vehicule` par rayons), relief (écart 0,00 cm).
- **Matériaux mis en cache par nom** : incrémenter `VERSION` à chaque changement, sinon l'ancienne version est réutilisée ; effet pervers : 2 226 assets fabriqués inutiles (38 versions de `EnduitBlanc`) → nommer sans version et supprimer l'ancien à la création. Une texture déjà importée n'est pas réimportée (supprimer les `.uasset`). Plancher de rugosité appliqué dans la fonction qui finalise tous les matériaux (`materiaux.finir`).
- **Navigation** : ne pas poser de volume ; la boîte de nav est calculée sur les bornes de **tous** les `StaticMeshActor` (l'horizon l'agrandit) → `BCM_NAV_OVERRIDE` (zone jouable + 10 m) calculé dans `rapport.json`, décor lointain en `Actor` nus (`NoCollision`, sans ombre, Nanite OFF) ou `--sans-lointain` ; **supprimer le `.umap`** avant reconstruction si une cuisson de nav l'a touché.
- **Zone jouable** : polygone (29 sommets, marge 60 m → 176×220 m), mur invisible 30 cm × 10 m ; **superposer la limite à la vue satellite AVANT construction** (la première limite coupait piscine, façade et terrasse).
- **Retouches du joueur** : `construire.bat` refait le niveau ENTIER et efface ses retouches → copie éditable jamais réécrite (`LC_REMPLACER=1`), lanceurs `A OUVRIR` (copie perso, dernière version générée en lecture seule, refaire la copie), inventaire avant/après (`inventaire_niveau.py`, `comparer_inventaires.py`), `decisions_utilisateur.json` rejoué à chaque construction. Instances groupées : cliquer une plante sélectionne toutes les instances → méthode de dégroupage documentée ; 6 215 → 377 acteurs, umap 20,3 → 12,3 Mo après regroupement.
- **Éditeur qui s'ouvre sur une carte vide** → `EditorStartupMap=/Game/Sandbox/<Carte>/<Carte>_Perso` dans `Config/DefaultEngine.ini` (ancien fichier gardé en `.avant_lc`) ; ne jamais demander au joueur d'ouvrir un projet à la main (lanceurs `.bat` avec carte explicite, vérifiés par capture).
- **Une carte de travail, plusieurs cartes livrées** : `LaCiotat_BP` à limites larges ; Hangar, Carrière, carte générale sortent du même code en ne changeant que les limites (décision du joueur du 14/11).
- **Contrôle visuel** : capture au point de vue de la photo réelle (pose calculée à < 6 px près par point de fuite, focale 26 mm), image côte à côte (réel à gauche), regarder, corriger, puis seulement le point suivant. Exposition de capture fixée par volume temporaire (`LC_EV` −0,5 ; le défaut −1 éclaircit tout de 40 %) ; **ne pas corriger la luminosité d'après les captures du joueur** (écran OLED). Un point de vue fixe par zone sert de contrôle visuel.

## 3. Paquetage et installation

- Chaîne : instantané `git archive` (lancé dans Git Bash : un tube PowerShell corrompt le flux binaire) + robocopy des assets (depuis PowerShell) → `lc_snap/pak_ue.bat construire --sans-lointain` (transmet les options à `construire_niveau.py`) → `paquetage.sh <version> "cook paks package [install]"` → `.bcmap`.
- Deux cartes partagent `Saved/Cooked` : construire l'une efface le cuit de l'autre. `ue_lock.sh` attend la fermeture de TOUT `UnrealEditor*.exe` : dans le clone de paquetage, ne regarder que le jeu et les Unreal portant le nom du projet (modification d'outil à signaler).
- Installation (jeu fermé) : `BodycamMapInstaller.exe --install <.bcmap> --yes` (`--list`, `--remove` ; `--list` n'imprime rien depuis PowerShell : utiliser Git Bash). Sortie : `z<Carte>_9_P.pak`, `z<Carte>_Modes_9_P.pak`, `zzMapCards_19_P.pak` dans `<JEU>/Content/Paks` (pak version 11) ; avant la v0.9 la carte apparaissait dans Play > Custom [vu]. Retour arrière : `--remove`, ou supprimer les `z*_P.pak` puis « Vérifier l'intégrité » Steam.
- Météo : défaut du kit `DA_DebugBadWeatherWeatherConfig` = orage/pluie ; `DA_PaintballWeatherConfig` = sec, retenu via `BCM_WEATHER`.
- Livraison au joueur : dossier de sortie daté (`AAAA-MM-JJ_HHhMM - Carte version`, nom sans `_` mal trié) + `LISEZ-MOI.txt`, chemin donné dans le chat à chaque paquetage ; double livrable « version jouable » + « version éditable ». **Ne jamais écrire « installé » sans un constat en jeu** : une passe « paquetage + installation » déclarée faite a été contredite trois fois par le joueur.
- Les scripts de livraison prennent leurs chemins en paramètre et vérifient la carte cible (un paquetage est parti sur la mauvaise carte parce que l'environnement du shell ne persiste pas entre appels).

## 4. Règle : essayer d'abord la carte d'exemple du kit

Avant toute construction de carte : faire installer et lancer la carte d'exemple `KitSample` fournie par le kit (10 minutes), sur la version courante du jeu. **Raison** : le blocage de la v0.9 est arrivé après 24 h de paquets inutilisables ; si l'exemple du kit n'apparaît pas non plus dans Play > Custom, le problème est côté jeu/installeur et aucun travail de décor ne le résoudra. Répéter ce test après chaque mise à jour du jeu (`buildid` Steam), surveiller le dépôt de l'installeur, et vérifier qu'une version du jeu charge encore des paks personnalisés avant d'investir. Si le test échoue : plan B = porter la même scène neutre vers Arma Reforger (`jeu_arma_reforger.md`) ou UEFN.

## 7. Pièges propres au jeu

- **« Je cours dans les airs »** : boîte de collision simple générée à l'import (3 016 rayons sur 3 016 la touchaient) → complexe-comme-simple + contrôle par rayons dès le début (§2).
- **Murs de hangar « troués en triangles »** : ordre des sommets contrôlé et écarté (0 triangle retourné sur 31 461) ; hypothèse retenue : Nanite activé dans le projet du kit (86 maillages) [NV-cause] ; corrigé « VU » en 0.1.1 après coupure de Nanite par maillage. Coller deux peaux aux murs, matériau deux faces pour tôle et toits minces.
- **Textures noires** (menuiserie, hangar central, murets) : matériau non assigné ou chemin cassé → contrôle sur TOUS les bâtiments, pas seulement celui signalé.
- **Portail enfoncé, voiture dans un mur ou roues dans le sol** : posés à la cote du terrain alors que la dalle est surélevée → bande de course aplanie, véhicules calés par rayons, sol de niveau sous l'objet.
- **Regressions** : le constructeur repartait d'une ancienne copie → un seul fichier de référence, historique git, lanceur « 0 - VERSIONS » (date de chaque carte), liste « NE PLUS TOUCHER ».
- **Normales/UV** : Unreal est main gauche ; sonde sur un triangle importé (identique 5.5/5.8 : M = diag(1,−1,1), V retourné) ; vérifier le sens du vert d'une normale avec une mire avant un import en masse ; Interchange 5.5 ignore les options `FbxImportUI` ; nœud Noise : ne pas relier Position, `NOISEFUNCTION_GRADIENT_ALU`.
- **Feuillage triplanaire sur buissons** → paillettes noires ; houppiers noirs à contre-jour → transmission 1,0 ; capture « surexposée » = écran OLED.
- **Banc de végétation** : premier lancement > 10 min (shaders) ; `r.SkinCache.CompileShaders=True` exigé dès que `r.RayTracing=True` ; recopier `RendererSettings` du kit ; lecture USD : `import pxr` plante sans `PXR_PLUGINPATH_NAME`.
- **Lointain** : service WMS rend la mer à −99999 ; garder le MNT avec de vrais arbres jusqu'à 450 m (le « tas de sable » vient d'une surface MNS posée à hauteur de cime) ; le décor lointain n'est **pas** dans les paquets (nav) ; maillage de houppiers 48 triangles par cellule de 9 m.
- **Outils Windows** : `python` du PATH = alias du Store (`py`) ; Pillow absent ; `Set-Content` PS 5.1 casse les accents ; heredoc Bash abîme les antislashs (écrire par l'outil d'écriture) ; `robocopy` échoue sous Git Bash ; journaux de construction en ANSI (`grep -a`) ; lanceurs `.bat` depuis PowerShell.
- **Assets** : modèle de 1 295 683 triangles et bornes nulles non posé (alléger d'abord) ; formats `.ztl`/`.blend` seuls inutilisables ; logo de fabricant visible sur des plaques importées ; plaques de remplissage de terre qui cachent les objets (supprimer plutôt que retoucher).
- **Quotas d'usage** : quatre agents lourds en parallèle ont vidé la fenêtre de 5 h en 35 min ; un constructeur sans plafond de tours a dépassé 400 000 jetons ; une passe de constructeur ≈ 18 % de la fenêtre et 3 % de la semaine → un seul constructeur à la fois, plafond écrit une seule fois.

- Moteur de la v0.9 (aucun changement annoncé) ; Landscape, foliage, Nanite, World Partition dans le kit ; import `.r16` en Landscape.
- Cause exacte des murs « troués » (Nanite supposé) ; effet de la météo du kit sur l'orangé général (supposé) ; tenue des cartes après une mise à jour du jeu (impossible à tester tant que le blocage dure).
- Menu de test UE4SS (jamais exécuté) ; paquet version 1 (`pc/unreal/construire_niveau.py`, jamais exécuté dans Unreal, testé avec un faux module).
